# 网页灯光控制台

Vue + TypeScript 单页应用，通过浏览器的 Web Serial（电脑串口）或 WebUSB（安卓 USB 直连）访问 Flipper Zero。

在线网址：https://vae-lightstick.guestliang.icu/

## 本地运行

需要 **Node.js 24 LTS**、**npm 12.2.1 或更新版本**，以及支持相应 USB 接口的 Chrome 或 Edge。

本项目固定使用 **Node.js 24.22.2**，版本记录在 `.node-version`；`package.json` 的 `engines.node` 限定为 `^24.22.2`，`packageManager` 记录 `npm@12.2.1`。

在本目录运行：

```sh
npm ci
npm run dev
```

打开终端显示的 <http://localhost:5173>。使用支持数据传输的 USB 线连接开机的 FZ，插好 microSD 卡，退出 FZ 上的其他应用并关闭占用串口的 qFlipper／其他网页，然后点击“连接 Flipper”。在浏览器弹窗中选择 FZ。

### 安卓串口列表为空时

在页面右上角选择 **安卓 USB 直连**，再点击“连接 Flipper”。这次应出现 **USB 设备**选择框，而不是串行端口选择框；在其中选择 Flipper Zero，允许浏览器访问。安卓会在浏览器提供 WebUSB 时默认选择这一方式。

USB 直连直接使用 FZ 的 CDC-ACM 数据接口，不依赖 Android 系统是否将它注册为串口。手机需要支持 USB Host／OTG，使用可传输数据的线，并访问部署后的 HTTPS 页面。如果 USB 设备列表仍为空，继续检查 OTG、数据线和浏览器的 USB 访问支持。

电脑继续使用 **电脑 USB 串口**；桌面系统的 CDC 驱动可能已经占用 USB 接口，USB 直连不作为桌面默认路径。普通 iPhone Safari 没有这两种网页 USB 接口，不能因更换为 USB-C 就使用本页面连接 FZ。

网页使用配套的 [FZ 原生应用](../native/README.md)，目前按 Unleashed `unlshd-094e`／F7 API `88.19` 编译。连接时读取 `device_info`、检查 SD 卡，校验设备上的应用文件，按需安装并启动，收到原生协议握手后才显示已连接。

## 使用

- **分组开关**：默认选择 G7、G8。打开表示参与本次发送，关闭表示不参与；开关本身不会发送无线信号，也不会覆盖该组的配色草稿。“展开全部 8 个分组”可以控制 G1–G8。
- **调色**：在调色盘上方点击 G7、G8 或其他已开启分组，选择当前要编辑的一组，再点击色块。每组独立保存配色，例如先给 G7 选红色，再给 G8 选蓝色，最后点击一次“发送颜色”，两组便按各自的配色发送。调色盘直接展示协议支持的 64 种颜色；每个分量只取 `0 / 85 / 170 / 255`，分别对应协议中的 `0 / 1 / 2 / 3` 档，黑色表示关闭。
- **我的双色**：内置红蓝、蓝红、紫青、双白四个 G7／G8 组合。点击后选择 G7、G8 并载入配色；普通模式需要再点击“发送颜色”，实时模式立即发送。其他组保留此前已发送的目标色。
- **实时模式**：连接后可开启，沿用上方分组开关，只让已选组亮白光，随后用鼠标划过或用手指按住拖过色块调色。选择 G7 只修改 G7、G8 保持原色；选择 G8 则相反。“统一操控”将当前颜色应用到所有已打开分组开关的组。调色期间不自动关灯，关闭实时模式时尝试发送全部关灯指令。
- **发送颜色**：通过短命令将八组颜色交给原生应用，默认约 2.096 秒后追加所选组的关闭帧。不选自动关灯时，发送结束后灯棒可以继续保持颜色；停止发射本身不会熄灯。
- **全部关灯**：与分组开关无关，发送完整八组关闭帧及旧七组关闭帧。关闭全部分组开关后仍能使用。
- **断开连接**：等待正在执行的发送结束并释放 USB，不额外发送关灯。连接和切换分组本身不会发射；普通模式点击颜色或预设只更新草稿，实时模式会发送颜色。

普通发送、模式切换和关灯都要等 FZ 返回完成结果，期间操作按钮会暂时禁用。实时调色时可以继续划过调色盘，正在发射的颜色完成后只发送最新配色，中途经过的旧颜色不会排队。同一配色停留不动时不重复发送，灯棒无需持续接收才能保持颜色。

### 实时调色与手动关灯

开启实时模式沿用上方分组开关和当前调色目标，只将已选组的配色设为白色；未选组沿用上次已发送的目标色。全部分组关闭时，开启实时模式不会发射，打开需要控制的组后即可调色。调色分组按钮决定本次滑动修改哪一组，分组开关决定该组是否参与控制；切换按钮本身不会改变灯光。实时模式中的双色预设会立即应用 G7／G8 各自的颜色。

实时颜色使用 3 帧短波形，波形本身约 196.5 ms。原生应用常驻，复用射频配置，直接从内存发射。同一台 FZ 的 USB CLI 测速约 216 ms／次，约 4.63 次／秒。调色盘旁显示网页最近一次命令从发送到收到完成回复的耗时，以及按该耗时换算的每秒更新次数。

点击“全部关灯”会丢弃尚未开始的实时配色，等正在发送的短波形结束后再发送关闭指令。关闭实时模式也会执行同样的关灯流程，并恢复普通发送按钮；分组选择和配色草稿保留。

**关闭网页、刷新、切换应用后被系统清理，或直接拔掉 USB，都不能保证送出关闭指令。** 页面记忆中仍有亮灯目标色时，会注册浏览器离页提醒，但手机等环境可能根本不触发该事件；页面无法在被终止后继续执行 USB 通信。离开前请点击“全部关灯”，确认实物熄灭，再关闭页面或断开连接。见 [MDN：beforeunload 的可靠性限制](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event#usage_notes)。

### “不控制该组”的具体含义

当前协议每一帧都包含完整的八组颜色，没有已知的“跳过某组”字段。网页会记住本次连接使用期间各组上次发送的目标色；发送新配色时，没有选中的组沿用这个值，自动关灯也只改变本次选择的组。首次打开网页时，这些记忆值均为关灯。

这份记忆无法读取灯棒被其他控制器设定的颜色，也不是灯棒当前状态。关闭分组开关不会立即熄灯，但后续发送仍然包含这个分组的颜色。网页与灯棒之间没有状态回传，界面中的“已发送”表示 FZ 报告执行成功。

配色草稿与已发送目标色分开保存：自动关灯或“全部关灯”之后，草稿仍在，可以直接再次发送同一个组合。刷新页面会重置草稿、选择和已发送目标色的记忆。

## 通信与设备文件

```text
Vue 页面 → Web Serial 或 WebUSB / USB CDC → FZ CLI
         → vae live / hold / auto / off
         → 常驻 FAP 在内存中构造波形 → 定时器／DMA → 荧光棒
```

原生应用使用 `433920000 Hz`、OOK 调制、250 µs Manchester 半位宽、1000 µs 同步低电平，以及本项目恢复的 16 字节格式。普通颜色与实时模式初始白光发送 32 帧，后续实时颜色更新发送 3 帧；自动关灯发送 16 帧；全部关灯额外发送 8 帧旧格式关闭序列。射频配置保留固件原 Ook650 的寄存器值，**在原生 C 常量中将 `PATABLE[1]` 固定为 `07`**，即近似 −25 dBm／0.0032 mW 低功率参考档（TI 典型值约 −25.3 dBm，实际辐射功率未测量）。所有颜色和关闭命令均使用同一配置。应用运行期间持有唤醒占用，退出后释放，不改写固件、自动电源设置或频段限制。

网页只在 FZ 的 `/ext/apps/vae-lightstick/vae_lightstick.fap` 安装／更新配套应用；MD5 相同时不重复上传。改色与关灯均不写 SD 卡，不依赖 `research/example-generate.py` 的输出。旧版网页生成的 `/ext/subghz/vae-lightstick-web/` 文件不再参与网页控制。

断开连接会退出本应用并释放 USB。意外关闭网页时，应用可能留在 FZ 屏幕上；下次连接会重新启动配套应用，也可以在 FZ 上按返回退出。设备睡眠、拔线、写入错误或回复超时后，页面会报告问题并释放串口，不会在后台自动重发。

## 构建

```sh
npm run build
npm run preview
```

`build` 先对 TypeScript 业务与通信代码进行类型检查，再编译 Vue 模板，并将配套 FAP 作为带内容哈希的资源一同输出到 `dist/`。可以部署到 HTTPS 静态站点，包括子路径。Web Serial 与 WebUSB 均需要安全上下文：本地使用 localhost，远程部署使用 HTTPS；直接双击 HTML 或通过普通 HTTP 局域网地址访问不适合作为串口入口。浏览器使用要求见 [MDN Web Serial API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Serial_API)。
